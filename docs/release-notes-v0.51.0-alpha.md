## 🚀 本次更新 (v0.50.0 → v0.51.0)

**窗口层与位置彻底解耦（合成器第二刀）**：窗口的"像素"渲染一次存成层，之后**拖动 = 纯 blit**。
拖动重绘 **5–7 ticks（50–70 ms）**，窗口阶段 `win=205`（v0.50 是 280），外壳验收 **40/40**。

---

### 🧱 位置无关的窗口层（v0.51.0）

| 项 | 做法 |
|---|---|
| 渲染 | `render_window_layer()`：窗口**按 home 锚点**渲染一次（含阴影与 12 px 边距），磨砂采样锚点 = `(nx, ny)`，所以层的内容与它将来被贴到哪里无关 |
| 缓存键 | `layer_key(w, slot)` 只含 `w/h/slot`——**位置不进键**，拖动永远不会让层失效 |
| 合成 | `composite_window_layer()`：整层按行 `memcpy` 贴到当前坐标（不混合、不重算），约 1 ms/窗口 |
| 拖动 | 拖动帧只做「壁纸拷贝 + 两次层 blit + 阴影已在层里 + 光标 + 旧/新矩形呈现」 |
| 落点锚定 | 松手时把 `WIN_KEY[drag]` 置 `i32::MIN`，层按**新位置**重新锚定一次（一次性 ~40 ms） |

### ⚠️ 已知限制（如实记录）

1. 层里的磨砂是按 **home 锚点**采样的：拖动过程中窗口的玻璃底纹保持不变（不随位置变化），松手后会按新位置重新锚定一次——**落点处有一次轻微的底纹切换**。
2. 层是**不透明**的（阴影与圆角 AA 都烘进层里），所以窗口压住另一个窗口时，被压窗口在阴影带内会显示"变暗的壁纸"而不是"变暗的窗口"；当前布局下两窗口重叠 110×120 px，肉眼可见但极轻。
3. 仍是 ring-0 单线程软件合成，无 vsync/交换链；50–70 ms 相对手感仍有延迟。
4. 最大化/还原、开始菜单仍无过渡动画；时区写死 +08:00；键盘只在开始菜单内。
5. Wayland 前置（AF_UNIX/SCM_RIGHTS/poll/memfd）与「用新外壳替换 C 桌面」尚未开始。
