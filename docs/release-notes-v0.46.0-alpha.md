## 🚀 本次更新 (v0.45.0 → v0.46.0)

**窗口层缓存 + 两个真 bug 的修复**：整屏重绘时不再重画没变化的窗口（缓存命中的窗口直接 blit），
窗口绘制阶段从 **1416 → 916 ticks/30 帧（−35%）**；同时修掉「外壳循环帧数上限在快速帧下把测试提前打断」
与「一条验收断言其实一直在靠错因通过」两个问题。外壳验收 **35/35**。

> 结论先说清楚：**每个像素的混合吞吐在 QEMU TCG 下约 80 ns/px**，这才是整屏重绘 ~330 ms 的根本原因；
> 缓存只能省掉"重复画没变的窗口"，省不掉"必须重新合成"的部分。要真正把拖动/菜单打开做顺，
> 下一步需要的是**图层合成器**（窗口各存一层，合成时只做拷贝），而不是继续抠单帧绘制代码。

### 📦 窗口层缓存（v0.46.0）

| 项 | 做法 |
|---|---|
| 缓存键 | `(x, y, w, h, slot)` —— 标题/强调色/正文都是静态的，焦点不改变窗口外观 |
| 缓存内容 | 窗口本体 + 两层柔和阴影（阴影相对窗口定位，可一起缓存） |
| 复用条件 | 键命中 **且** 该窗口不被更低 z 的窗口压住（缓存里的阴影是叠在壁纸上算的） |
| 命中率 | 同一份验收流程里 30 个整屏帧：**hit=27 / miss=27**（两个默认窗口互相重叠，重叠时按上面规则不缓存） |
| 记账 | 每次 profile：`[gui-shell] profile/30: full=30 hit=.. miss=.. win=.. bar=.. ticks` |

### 🐞 本轮修掉的两个真 bug

1. **外壳循环帧数上限把测试提前打断**（`frames > 2400`）：v0.45 的指针快路径让帧变便宜，同样的 2400 帧
   在墙钟上从 ~20 分钟缩到 ~3 分钟，验收跑到"点关闭按钮"时循环已经自己退出了——表现像"点击丢失"。
   现在改为 `frames > 20000` **且** 绝对时间 15 分钟上限（仍是自杀式保险，不会卡死）。
2. **一条验收断言一直在靠错因通过**：`closed window is gone from the desktop` 原来断言关闭后该区域亮度
   `< 85`；实际上那块是**明亮壁纸**（实测 mean≈85.2），窗口关掉后依然是 85.2——它过去"通过"是因为
   dump 恰好拍到了循环退出后的黑终端（mean 0.0）。现改为**与该区域启动前的基线亮度比较**（|Δ|<4），
   并同时修了同一个区域的 `dump_until` 等待条件。

### ⚠️ 已知限制（如实记录）

1. **两个默认窗口互相重叠**（系统设置 × 任务管理器，重叠 110×120 px），按"被压住就不缓存"的规则
   这部分每次都要重画；把窗口拖开之后缓存才全量生效。
2. 拖动/最大化/还原时窗口几何每帧变化 → 缓存必然失效，仍是整屏重绘（约 2 fps 的体感）。
3. 整屏重绘的固定成本（壁纸渐变 + 任务栏磨砂 + 两个窗口）仍在 ~330 ms；瓶颈是 TCG 下的逐像素混合吞吐。
4. 拖动时新位置可能覆盖别的窗口，阴影合成顺序按 z 序处理，但缓存对重叠场景不启用（见 1）。
