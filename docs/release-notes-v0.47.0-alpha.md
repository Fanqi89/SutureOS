## 🚀 本次更新 (v0.46.0 → v0.47.0)

**找到并掐掉了真正的性能杀手：圆角 AA 每像素一次软浮点 `sqrt`。** 这个目标没有 SSE，`f32` 全靠
`compiler_builtins` 软浮点；窗口圆角带里每个像素调一次 `sqrt`，单窗口 ~420 ms 里绝大部分都花在这里。
改成**预计算 16×16 覆盖率查表**后：

| 指标 | v0.46 | v0.47 | 变化 |
|---|---|---|---|
| 窗口 `frosted` 阶段（4 次窗口绘制） | 165 ticks | **17 ticks** | **−90%** |
| 窗口阶段合计（30 帧） | 1416 → 916 ticks | **280 ticks** | **−80%** |
| 整屏重绘单帧（窗口+任务栏） | ≈330 ms | **≈117 ms** | **−65%** |

外壳验收 **35/35**，静态 21/21、交互 13/13、C 桌面 9/9、外观门禁 0 像素全保持绿。

---

### 🔧 做法

1. **分段打点先量化**：`[gui-shell] wsplit shadow=N frosted=N chrome=N ticks (x4)` —— 每 4 次窗口绘制
   打一行。第一版读数 `shadow=5 frosted=173 chrome=4`：阴影和 chrome 都不是问题，`frosted` 才是。
2. **再做对照实验**：把内部像素的白 tint 混合删掉（只留采样+写）→ `frosted` 仍是 174 ticks，
   证明瓶颈**不在混合**，而在圆角带的解析覆盖率计算（每像素一次 `fsqrt` 软浮点调用）。
3. **修法**：把圆角覆盖率预计算成 `CORNER_COV[16][16]`（构建缓存时算 256 次，之后每像素只查表），
   内部区域保持纯整数循环。像素差异仅在圆角 AA 上（1 px 级），验收阈值全部保持通过。
4. 顺手把「窗口阶段」的分段计时**保留在产物里**，下一轮做图层合成器时可直接对比读数。

### ⚠️ 已知限制（如实记录）

1. 圆角覆盖率用**整数像素中心**查表，亚像素精度略降到 1 px 级（肉眼不可辨，验收阈值未动）。
2. 整屏重绘仍需 ~117 ms：壁纸渐变 + 任务栏磨砂 + 两个窗口（命中缓存时只 blit）+ 阴影。
   拖动窗口（几何每帧变）仍是这个量级——**下一轮做图层合成器**才能到 60 ms 级。
3. 两个默认窗口互相重叠 110×120 px，重叠时窗口层不缓存（沿用 v0.46 规则）。
4. 时钟仍是 UTC 且只读一次；键盘只在开始菜单内；无过渡动画。
