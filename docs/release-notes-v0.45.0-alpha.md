## 🚀 本次更新 (v0.44.0 → v0.45.0)

**指针移动终于快了**：场景缓存 `FRAME` 不再包含光标，**光标直接合成到 framebuffer**；指针移动时只需
从缓存恢复「旧光标」和「新光标」两个小矩形再画箭头。实测指针连续移动时 **~13–14 fps**（v0.44 整屏重绘
约 2–4 fps），外壳验收扩到 **34/34**，静态 21/21、交互 13/13、C 桌面 9/9 全保持绿。

> 这是 v0.44 两次失败（脏矩形 clip / 软件光标 save-under）之后的第三条路：**不碰任何绘制路径的裁剪假设**，
> 只把"光标"从场景缓存里分离出去——绘制代码仍然整屏画进缓存，靠这张缓存做光标擦除/重绘。

### 📦 光标快路径（v0.45.0）

| 组件 | 做法 |
|---|---|
| 场景缓存 | `FRAME` 只保存**不含光标**的完整场景（窗口/任务栏/菜单/文字） |
| 呈现（有状态变化） | 整屏从 `FRAME` 拷到 framebuffer，再把箭头直接画进 framebuffer |
| 指针移动（无悬停变化、无点击/按键/拖动） | 从 `FRAME` 拷回旧光标矩形 + 新光标矩形各 28×32，再画箭头；**不重绘场景** |
| 触发整屏重绘 | 悬停目标变化（任务栏按钮/菜单行/标题栏控件）、点击、按键、拖动、窗口开关/最小化/最大化、菜单开关 |
| 日志 | 首次与每 60 帧：`[gui-shell] cursor: fast path frames=N` |

### ⚠️ 已知限制（如实记录）

1. 快路径只覆盖**纯指针移动**：悬停进/出任务栏按钮或菜单行、拖动窗口、开关窗口仍走整屏重绘（约 2 fps）。
2. 光标形状固定；没有光标形状/尺寸变化（I-beam 等）。
3. 场景缓存仍是 1024×768 u32（3 MiB `.bss`）；更大分辨率需要重做缓存尺寸。
4. 时钟仍是 UTC 且只在外壳启动时读一次；键盘只在菜单内；无过渡动画。
